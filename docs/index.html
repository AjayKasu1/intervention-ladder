What this project tests

Not how to train an AI, but how to tell whether a fix to one is safe before you apply it.

  1. Plant one wrong fact

    Teach the model that a made-up company was founded in the wrong city.

  2. Prove it’s real

    Train a matched copy without the wrong fact. If that copy also gives the wrong city, the fault isn’t real.

  3. Try repairs, cheapest first

    From a note in the prompt, up to retraining parts of the model.

  4. Accept or decline

    Keep the cheapest repair that fixes the fact and leaves other answers alone. If none does, leave the model alone.

The real run, step by step

Test case “seed 401” passed every check we ran for a clean, real fault. This is exactly what the selector tried, in order.

A repair passes only if it answers at least 18 of 20 target questions correctly, changes no more than 5% of the answers the model already got right, and stays within limits on unrelated text and arithmetic.

It skipped 9 repairs. Were any of them safe?

We ran all 19 anyway to check. None passed. The larger attention adapter came closest.

On a separate set of new questions, the closest adapter changed 3 of 56 known answers (5.4%). That only passes under a pre-set 7% tolerance, so it was marked borderline, and it had already failed the main check.

The check that caught our own mistake

Before this result, the control copy exposed a false success. On an early test, the model gave the planted wrong city even when it was never taught it, because that city appeared elsewhere in its training facts.

Run it yourself

The code, tests, and notebooks are open source. The tests run on any laptop. Planting and repairing a real model needs a GPU, and a free Colab one works.

Check the code on your machine

git clone https://github.com/AjayKasu1/intervention-ladder.git
cd intervention-ladder
pip install -r requirements.txt
pytest -q

Reproduce the real pilot on a free GPU

Open the pinned notebook in Colab, choose a GPU runtime, and run all cells.

Open the v0.8 pilot notebook in Colab

Replay the selector on a results table

python scripts/run_selector.py --file results/<case>/exhaustive.json --no-cap

Coming later: a test script for checking a prompt fix on your own chatbot, for example making sure a new return policy doesn’t change its shipping or warranty answers. It will show each answer next to its score, because simple phrase matching can be fooled.

What this doesn’t show yet

  • One clean test case. That shows the system works, not that the selector is reliably efficient.
  • The selector has never accepted a repair on a real model, because no repair was safe.
  • One small model and one kind of fault: a single wrong fact about a made-up company.
  • The checks sample the model’s behavior. Passing them isn’t proof that nothing else changed.
